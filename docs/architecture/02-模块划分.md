## 1. 文档目的

本文档定义企业智能体统一门户平台的模块划分方案，包括前端模块、后端微服务、公共能力组件，明确各模块职责、边界和交互关系。

### 3.2 子模块详情

#### 3.2.1 门户首页 (Portal)

| 要素 | 说明 |
|---|---|
| **定位** | 业务用户登录后的默认落地页 |
| **核心功能** | 欢迎横幅、最近使用的 Agent、推荐 Agent、未读通知、快捷搜索 |
| **技术要点** | 数据通过 `/api/portal/dashboard` 聚合接口一次性获取，减少首屏请求数 |

#### 3.2.2 Agent 市场 (Marketplace)

| 要素 | 说明 |
|---|---|
| **定位** | 企业 Agent 的发现和浏览入口 |
| **核心功能** | 分类筛选、关键词搜索、Agent 详情页、使用/收藏/评分 |
| **技术要点** | 虚拟滚动（大量 Agent 时）、骨架屏加载态、分页+搜索参数同步到 URL |

#### 3.2.3 我的 Agent (My Agents)

| 要素 | 说明 |
|---|---|
| **定位** | 用户已安装/已收藏/最近使用的 Agent 集合 |
| **核心功能** | Agent 列表（可分组）、对话入口、使用统计、卸载/取消收藏 |
| **技术要点** | 与市场复用同一 AgentCard 组件，通过 `source` 属性区分数据来源 |

#### 3.2.4 管理中心 (Admin)

| 要素 | 说明 |
|---|---|
| **定位** | IT 管理员和开发者的管理后台 |
| **核心功能** | Agent 生命周期管理（创建/编辑/发布/下线）、平台连接管理、用户权限管理、审计日志查看 |
| **技术要点** | 动态表单（Agent 配置 Schema 随平台适配器变化）、批量操作、操作确认弹窗 |

#### 3.2.5 对话页面 (Chat)

| 要素 | 说明 |
|---|---|
| **定位** | 与 Agent 进行实时对话的交互界面 |
| **核心功能** | 消息列表（支持 Markdown 渲染）、流式输出（SSE / WebSocket）、多轮对话、对话历史 |
| **技术要点** | 虚拟滚动消息列表、Markdown + 代码高亮、打字机效果（streaming）、复制/重新生成/反馈 |

#### 3.2.6 系统公共模块 (System Common)

| 要素 | 说明 |
|---|---|
| **定位** | 全局共享的布局、导航、通用逻辑 |
| **核心功能** | 顶部导航、侧边栏（管理中心）、用户头像下拉菜单、全局搜索、通知中心 |

## 4. 后端服务

### 4.1 服务总览

| 服务名 | 端口 | 职责 | 依赖 |
|---|---|---|---|
| **gateway** | 80/443 | 统一入口，反向代理，限流 | 无 |
| **users** | 8001 | 用户注册/登录/认证/权限管理 | PostgreSQL, Redis |
| **agents** | 8002 | Agent 元数据管理、市场/商店逻辑 | PostgreSQL |
| **adapters** | 8003 | 平台适配层，对接外部 Agent 平台 | PostgreSQL, Redis |
| **chat** | 8004 | 对话会话管理、消息路由、流式转发 | PostgreSQL, Redis, adapters |
| **monitor** | 8005 | 使用统计、日志聚合、告警 | PostgreSQL |

## 5. 公共能力层

### 5.1 认证中心 (Common Auth)

内嵌于 `users` 服务，但作为公共模块向其他服务提供中间件：

```
common/auth/
├── jwt_handler.py              # JWT 签发、验证、刷新
├── dependencies.py             # FastAPI 依赖：get_current_user, require_role
├── rbac.py                     # 角色-权限检查引擎
├── tenant_context.py           # 当前租户上下文解析
└── exceptions.py               # 认证异常定义
```

**关键能力**：
- `Depends(get_current_user)` → 从请求头解析 JWT，注入 `CurrentUser`
- `Depends(require_role("admin"))` → 角色检查装饰器
- `Depends(get_current_tenant)` → 从 JWT 或 Header 解析 `tenant_id`

### 5.2 审计日志 (Common Audit)

```
common/audit/
├── audit_logger.py             # 审计日志写入器
├── audit_middleware.py         # 自动记录 API 调用
├── models.py                   # AuditLog 模型
└── decorators.py               # @audit_action 装饰器
```

**审计日志字段**：
- `tenant_id` — 租户 ID
- `user_id` — 操作用户
- `action` — 操作类型（CREATE / READ / UPDATE / DELETE / EXECUTE）
- `resource_type` — 资源类型（agent / connection / session / user）
- `resource_id` — 资源 ID
- `detail` — JSONB 操作详情
- `ip_address` — 来源 IP
- `user_agent` — 客户端标识
- `timestamp` — 时间戳
- `result` — 操作结果（success / failure）

## 6. 服务间通信

### 6.1 通信方式

| 场景 | 方式 | 说明 |
|---|---|---|
| 同步查询（如 chat → adapters 查询 Agent 信息） | HTTP REST（httpx async） | 服务间内部调用，带重试和超时 |
| 实时推送（如 adapters 流式消息 → chat） | SSE / WebSocket 透传 | 对话场景，低延迟流式输出 |
| 异步事件（如 agent 发布 → 通知所有安装者） | Redis Pub/Sub | 解耦服务，支持多消费者 |
| 定时任务（使用统计聚合） | APScheduler（轻量）或 Celery | 可选 Celery + Redis Broker |

### 6.2 服务调用链路示例

```
用户发消息 "帮我分析这份数据"
  │
  ▼
[chat 服务]
  │ 1. 创建/查找 Session
  │ 2. 保存用户消息
  │ 3. 请求 adapters 服务 → 路由到对应平台适配器
  ▼
[adapters 服务]
  │ 4. 匹配 Agent → 平台连接
  │ 5. 调用平台 API（如 Dify Chat API）
  │ 6. 通过 SSE 逐 token 返回
  ▼
[chat 服务]
  │ 7. 逐 token 转发给前端
  │ 8. 对话结束后保存完整消息到 Redis + PostgreSQL
  │ 9. 触发使用统计事件（Redis Pub/Sub）
  ▼
[monitor 服务]
  │ 10. 消费统计事件，更新使用记录
```

## 7. 模块间的关键接口契约

### 7.1 agents 服务 → adapters 服务

```
POST /internal/adapters/{agent_id}/capability
  → 查询某个 Agent 的能力描述（对话类型、参数 Schema）
```

### 7.2 chat 服务 → adapters 服务

```
POST /internal/adapters/chat
  → 发起对话请求，返回 SSE 流
  请求体：{ agent_id, session_id, message, context }
  响应：SSE event stream (text/event-stream)
```

### 7.3 chat 服务 → agents 服务

```
GET /internal/agents/{agent_id}/public-info
  → 获取 Agent 的基本信息（名称、描述、图标），用于对话页头部展示
```

### 7.4 各服务 → users 服务

```
GET /internal/users/verify
  → 验证 JWT Token 有效性（内部调用，不走网关）
  Headers: Authorization: Bearer <token>
```
