# 07 — 开发路线图

> 版本：v1.0 | 日期：2026-06-28 | 状态：设计阶段

---

## 1. 文档目的

本文档定义企业智能体统一门户平台的分阶段开发路线图，明确各 Phase 的目标、交付物、里程碑和技术风险，为项目管理和迭代规划提供依据。

---

## 2. 总体时间线

```
Phase 1 (MVP)          Phase 2                Phase 3               Phase 4
核心门户 + 认证         市场完善 + 对话引擎     平台适配器 + 管理后台    高级功能
[══════ Week 1-4 ════][══════ Week 5-8 ════][══════ Week 9-14 ═══][══ Week 15+ ══]
      ▲                      ▲                      ▲                   ▲
      │                      │                      │                   │
   里程碑 1               里程碑 2              里程碑 3             里程碑 4
```

## 3. Phase 1：核心门户 + 用户认证 + Agent 抽象模型（MVP）

**时间**：Week 1-4 | **优先级**：P0（必须完成）

### 3.1 目标

建立一个可运行的最小可行产品：用户能注册/登录，管理员能创建 Agent 并发布到市场，终端用户能浏览 Agent 列表。

### 3.2 功能清单

| 模块 | 功能 | 优先级 |
|---|---|---|
| **用户认证** | 邮箱注册/登录 | P0 |
| | JWT Token 签发与刷新 | P0 |
| | 个人信息查看/编辑 | P1 |
| | 密码修改 | P1 |
| **用户管理** | 角色体系（super_admin / admin / user） | P0 |
| | 邀请用户加入租户 | P2 |
| **Agent 管理** | Agent 创建/编辑/删除（统一抽象模型） | P0 |
| | Agent 版本管理（草稿/发布/归档） | P1 |
| | 分类和标签管理 | P1 |
| **Agent 市场** | Agent 列表浏览（分页、分类筛选） | P0 |
| | Agent 详情页 | P0 |
| | Agent 搜索（关键词 + 标签） | P1 |
| | Agent 安装/卸载 | P1 |
| **门户首页** | 登录后落地页（最近使用 + 推荐占位） | P1 |
| **平台连接** | 平台连接 CRUD（仅管理连接配置，不做实际对接） | P1 |
| **多租户** | tenant_id 隔离 | P0 |
| **审计日志** | 核心操作日志记录 | P1 |

### 3.3 技术交付物

| 交付物 | 说明 |
|---|---|
| 数据库 Schema | 全部表的 DDL + Alembic 迁移脚本 |
| users 服务 | 注册/登录/认证/JWT/角色管理 |
| agents 服务 | Agent CRUD + 市场列表/搜索 |
| adapters 服务 | 平台连接管理（仅配置，无实际适配器） |
| 前端门户 | 登录/注册页面、Agent 市场、Agent 详情 |
| 前端管理 | Agent 创建/编辑、连接管理 |
| Docker Compose | 完整开发环境一键启动 |
| 测试覆盖 | 后端 ≥80% 单元测试覆盖率 |
| API 文档 | FastAPI 自动生成 OpenAPI + 前端 API 封装 |

### 3.4 不做的事

- ❌ 不对接任何外部平台（Dify/N8N/Coze）
- ❌ 不实现对话功能
- ❌ 不实现 SSO
- ❌ 不实现推荐算法
- ❌ 不实现文件上传

### 3.5 里程碑验收标准

- [ ] 用户可以注册和登录
- [ ] 管理员可以创建 Agent、设置分类和标签、发布到市场
- [ ] 用户可以在市场浏览和搜索 Agent
- [ ] 用户可以将 Agent 安装到"我的 Agent"
- [ ] 多租户数据隔离生效（租户 A 看不到租户 B 的 Agent）
- [ ] 所有后端测试通过，覆盖率 ≥80%
- [ ] Docker Compose 一键启动全部服务
- [ ] OpenAPI 文档可访问且完整

## 4. Phase 2：Agent 市场完善 + 对话引擎 + 文件存储

**时间**：Week 5-8 | **优先级**：P0

### 4.1 目标

完善 Agent 市场体验（评分/评论/收藏/图标），构建通用对话引擎（会话管理 + 消息存储 + 流式输出），集成文件存储。**平台适配器（Dify/N8N/Coze）全部跳过，待后续决策后统一推进。**

### 4.2 功能清单

| 模块 | 功能 | 优先级 |
|---|---|---|
| **对话引擎（通用）** | 会话创建/管理（不与外部平台对接，仅做本地会话） | P0 |
| | 消息历史（Redis 热缓存 + PostgreSQL 冷归档） | P0 |
| | 对话页面（消息气泡 + Markdown 渲染） | P0 |
| | 流式输出前端（打字机效果，SSE 协议） | P0 |
| | 对话反馈（like/dislike） | P1 |
| | 会话归档 | P2 |
| **Agent 市场完善** | Agent 评分与评论（已有基础，完善） | P0 |
| | 我的 Agent 页（已安装 + 最近使用） | P0 |
| | Agent 收藏 | P1 |
| | 首页推荐（基于热度，无算法） | P1 |
| | Agent 图标上传 | P1 |
| **文件存储** | MinIO / S3 集成 | P1 |
| | Agent 图标上传 | P1 |
| | 对话附件准备（仅存储层，不下发） | P2 |
| ~~**Dify 适配器**~~ | ⏸️ 跳过（待后续决策） | — |
| ~~**N8N 适配器**~~ | ⏸️ 跳过（待后续决策） | — |
| ~~**Coze 适配器**~~ | ⏸️ 跳过（待后续决策） | — |

### 4.3 技术交付物

| 交付物 | 说明 |
|---|---|
| chat 服务 | 通用对话引擎：Session + Message（本地） + SSE Stream 框架 |
| 对话前端 | 对话页面、流式渲染、历史消息 |
| 文件存储 | MinIO 集成（Agent 图标 + 对话附件存储层） |
| 适配器注册表框架 | BaseAdapter 抽象 + AdapterRegistry 注册表（不实现具体适配器） |
| 集成测试 | chat 服务 → 前端 对话端到端测试（使用 mock 适配器） |

### 4.4 里程碑验收标准

- [ ] 用户可以从 Agent 详情页进入对话（通用对话引擎，暂时无外部平台对接）
- [ ] 对话支持流式输出（SSE），打字机效果流畅
- [ ] 多轮对话上下文正确维护（本地存储）
- [ ] 对话历史可查看，支持跨设备恢复会话
- [ ] 用户可以对 Agent 评分和评论
- [ ] Agent 图标可上传并正确展示
- [ ] 适配器注册表框架就绪（BaseAdapter + Registry），可随时接入新平台
- [ ] 文件存储（MinIO）可正常工作

## 7. 风险管理

### 7.1 技术风险

| 风险 | 影响 | 概率 | 缓解措施 |
|---|---|---|---|
| **多租户数据泄漏** | 严重安全事故 | 低 | RLS + 中间件 + 代码审查 + 安全测试 |
| **SSE 长连接资源耗尽** | 服务不可用 | 中 | 连接池限制 + 超时自动断开 + 水平扩展 |
| **PostgreSQL 性能瓶颈** | 查询变慢 | 低 | 索引优化 + 读写分离 + 分区表（Phase 3+） |

### 7.2 进度风险

| 风险 | 影响 | 概率 | 缓解措施 |
|---|---|---|---|
| **Phase 1 范围蔓延** | 延期交付 | 中 | 严格 MVP 定义，"不做的事"清单约束 |
| **平台适配器开发** | Phase 3 延期 | 中 | 适配器已标记跳过，后续按需启动 |
| **前端 UI 需求反复** | 延期和返工 | 中 | 使用 Element Plus 标准组件，减少自定义 UI |

### 7.3 依赖风险

| 依赖 | 影响 | 缓解措施 |
|---|---|---|
| Dify API 稳定性 | 适配器调用失败 | ⏸️ 跳过 Dify 适配器，暂不关注 |
| N8N 工作流输出格式不统一 | 响应提取失败 | ⏸️ 跳过 N8N 适配器，暂不关注 |
| Coze API 限流 | 对话中断 | ⏸️ 跳过 Coze 适配器，暂不关注 |

## 10. Phase 间依赖关系

```
Phase 1 (MVP)
  ├── 用户认证 & 多租户 ────────────────┐
  ├── Agent 抽象模型 & 市场 ────────────┤
  └── 平台连接管理（配置） ─────────────┤
                                       │
Phase 2                               │
  ├── 对话引擎 ← 依赖 Agent 模型 + Session/Message 表（Phase 1）
  ├── 市场完善（评分/评论/收藏） ← 依赖 Agent 模型（Phase 1）
  └── 文件存储（MinIO） ← 独立组件

Phase 3
  ├── 平台适配器（⏸️ Dify / ⏸️ N8N / ⏸️ Coze）← 依赖适配器框架 + 对话引擎（Phase 2）
  └── 管理后台 ← 依赖全部服务

Phase 4
  ├── 推荐系统 ← 依赖使用数据（Phase 2+）
  ├── SSO ← 依赖用户系统（Phase 1）
  └── 国际化 ← 依赖前端框架（Phase 1）
```

**并行开发可能**：
- Phase 2 中对话引擎与文件存储可并行开发
- Phase 3 中各平台适配器可并行由多名后端开发
- Phase 4 的各项功能相互独立，可按优先级逐个交付
