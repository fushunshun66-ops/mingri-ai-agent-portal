## 4. Agent 统一抽象模型

### 4.1 设计目标

不同平台的 Agent 概念差异大（Dify 是"应用"、N8N 是"工作流"、Coze 是"Bot"），需要在门户层提供统一的 Agent 抽象，让用户感知不到底层平台差异。

### 4.2 platform_config — 平台特定配置

此 JSONB 字段存储不同平台的特有参数，是屏蔽差异的核心字段：

```json
// Dify 平台
{
  "connection_id": "uuid",              // 关联的平台连接
  "app_id": "dify-app-uuid",           // Dify 应用 ID
  "mode": "chat",                       // completion / chat / workflow
  "opening_statement": "你好，我是...",  // 开场白
  "suggested_questions": ["问题1", "问题2"],
  "file_upload_enabled": true,
  "speech_to_text_enabled": false
}

// N8N 平台
{
  "connection_id": "uuid",
  "workflow_id": "n8n-workflow-id",    // N8N 工作流 ID
  "trigger_type": "webhook",            // webhook / form / chat
  "webhook_path": "/webhook/xxx",
  "input_format": "json",               // json / form-data
  "response_path": "$.output",          // JSONPath 提取响应
  "polling_enabled": false              // 是否轮询模式（异步工作流）
}

// Coze 平台
{
  "connection_id": "uuid",
  "bot_id": "coze-bot-id",
  "version": "v3",
  "opening_dialog": "你好！",
  "knowledge_name": "企业知识库",
  "plugin_ids": ["plugin-1", "plugin-2"]
}
```

### 4.5 平台差异屏蔽策略总结

| 差异维度 | 屏蔽方式 |
|---|---|
| **Agent 概念不统一**（应用/工作流/Bot） | 统一为 `Agent` 实体，`platform_type` 标识来源 |
| **配置参数不同** | `platform_config` JSONB 存储平台特有字段 |
| **调用方式不同**（REST/Webhook/gRPC） | 适配器内部处理，对外暴露统一调用接口 |
| **能力范围不同**（对话/工作流/表单） | `capability` JSONB 描述能力，前端据此渲染不同 UI |
| **输入输出格式不同** | `input_schema` / `output_schema` 用 JSON Schema 统一描述 |
| **流式输出协议不同**（SSE/WebSocket/轮询） | 适配器统一封装为 SSE，chat 服务只处理 SSE |
| **认证方式不同**（API Key/Bearer Token/Basic Auth） | `platform_connections.config` 存储加密凭证，适配器负责注入 |

## 5. 多租户数据隔离方案

### 5.1 隔离策略

标品默认采用 **共享数据库 + tenant_id 行级隔离**：

```
-- 启用行级安全
ALTER TABLE agents ENABLE ROW LEVEL SECURITY;

-- 创建策略：只能读取本租户的 Agent
CREATE POLICY tenant_isolation ON agents
  USING (tenant_id = current_setting('app.current_tenant_id')::uuid)
  WITH CHECK (tenant_id = current_setting('app.current_tenant_id')::uuid);
```

### 5.2 应用层保障

- 所有 Repository 查询默认带上 `tenant_id = current_tenant.id` 条件
- FastAPI 中间件自动从 JWT 解析 `tenant_id`，设置到 `app.current_tenant_id` 上下文变量
- 审计日志记录所有跨租户访问尝试（即使被 RLS 拦截）

### 5.3 未来扩展

大客户可选择 **独立数据库** 模式，通过修改数据库连接字符串实现，应用代码不需改动（因为所有查询已带 tenant_id，独立模式下即使多租户 id 相同也不冲突）。
