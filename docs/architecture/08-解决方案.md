## 1. 文档目的

本文档阐述企业智能体统一门户平台的产品定位、核心价值、功能全景与差异化竞争力，回答"这个产品做什么、怎么做、为什么选它"。

---

## 2. 产品定义

### 2.1 一句话定位

> **企业智能体统一门户**——企业内部 AI 能力的"总控台"，让员工像逛应用商店一样发现和使用 AI Agent。

### 2.2 核心比喻

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                   │
│     如果把 Dify / N8N / Coze 比作不同的「发电厂」，                 │
│                                                                   │
│     那本产品就是「国家电网」——                                     │
│                                                                   │
│     ✅ 统一接入：不管电从哪个厂来，用户只有一个插座                   │
│     ✅ 按需调度：用户不需要关心底层是哪个平台在服务                   │
│     ✅ 安全计量：统一计费、审计、权限管控                            │
│     ✅ 市场流通：好的 Agent 可以在企业内被发现、安装、使用            │
│                                                                   │
└──────────────────────────────────────────────────────────────────┘
```

### 2.3 产品边界

| 我们做什么 | 我们不做 |
|---|---|
| ✅ 统一门户：Agent 发现、安装、使用入口 | ❌ 不做 Agent 开发平台（不替代 Dify/N8N/Coze） |
| ✅ 平台适配：对接主流 Agent 平台的 API | ❌ 不做 LLM 推理（不替代模型服务） |
| ✅ 用户市场：内部 Agent 发布、发现、评分 | ❌ 不做即时通讯（不替代钉钉/企微，但可集成） |
| ✅ 统一管理：权限、审计、监控、统计 | ❌ 不做底层自动化（不替代 RPA） |

## 3. 核心价值主张

### 3.1 对业务用户：一个入口，所有 AI

| 痛点 | 解决方案 |
|---|---|
| 不知道公司有哪些 AI 可用 | **Agent 市场**：分类浏览 + 搜索 + 推荐 |
| 多个平台多个账号来回切换 | **统一认证**：一个账号，无缝使用所有 Agent |
| 找不到之前用过的 Agent | **我的 Agent**：已安装、最近使用、收藏夹 |
| 不知道该用哪个 Agent | **评分与评论**：同事的真实使用反馈 |

### 3.2 对 Agent 开发者：一次发布，全员可见

| 痛点 | 解决方案 |
|---|---|
| 做好的 Agent 没人知道 | **发布到市场**：全企业可见，支持分类和标签 |
| 不知道有多少人在用 | **使用统计**：安装数、调用次数、活跃用户 |
| 不知道该改进什么 | **用户反馈**：评分评论、对话记录分析 |
| 跨平台开发要学多套东西 | **统一抽象模型**：一套 API 对接所有平台 |

### 3.3 对 IT 管理员：统一治理，安全可控

| 痛点 | 解决方案 |
|---|---|
| 不知道公司有多少 Agent 在跑 | **管理仪表盘**：Agent 总数、平台分布、活跃度 |
| API Key 散落各处，安全风险高 | **集中凭证管理**：加密存储、权限控制、使用审计 |
| 无法追踪谁用了什么 | **审计日志**：全操作记录，谁何时做了什么 |
| 多平台权限体系不一致 | **统一 RBAC**：跨平台统一角色和权限 |

## 5. 典型业务场景

### 5.1 场景一：新员工入职日

```
小王今天入职市场部。

上午 10:00  — IT 管理员已为小王开通企业 AI 门户账号
上午 10:15  — 小王登录门户，在 Agent 市场看到：
              · 智能客服助手（4.8⭐，328 人使用）
              · 数据分析 Bot（4.5⭐，156 人使用）
              · 文档翻译助手（4.7⭐，89 人使用）
上午 10:20  — 小王安装"文档翻译助手"，立即开始使用
上午 11:00  — 小王用"数据分析 Bot"分析了一份竞品报告

全流程无需 IT 支持、无需申请权限、无需学习新平台。
```

```
张工（IT 管理员）打开管理仪表盘：
```

### 5.3 场景三：Agent 开发者发布新应用


## 6. 差异化竞争力

### 6.1 与现有方案的本质区别

| 维度 | Dify 管理后台 | N8N 仪表盘 | 企业 IM Bot | **本产品** |
|---|---|---|---|---|
| 跨平台 Agent 管理 | ❌ 仅 Dify | ❌ 仅 N8N | ❌ 单来源 | ✅ 多平台统一 |
| Agent 应用市场 | ❌ | ❌ | ❌ | ✅ 内部商店 |
| 终端用户自助发现 | ❌ | ❌ | 部分 | ✅ 搜索/浏览/推荐 |
| 统一审计与权限 | 弱 | 弱 | 无 | ✅ 全平台覆盖 |
| 平台无关性 | ❌ | ❌ | ❌ | ✅ 插件化热插拔 |
| 开箱即用 | 部分 | 部分 | 是 | ✅ 标品化 |

### 6.2 核心竞争力总结

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   🎯 平台无关    — 不是"又一个 Agent 平台"，而是所有平台的入口  │
│   🏪 内部市场    — 让 AI 能力在企业内像应用商店一样流通        │
│   👤 终端友好    — 业务用户不需要懂技术，打开即用              │
│   🔒 安全可控    — 统一凭证管理、审计全覆盖、权限精细化         │
│   📦 标品交付    — Docker Compose 一键部署，开箱即用          │
│   🔌 开放生态    — 插件化适配器，新增平台 4 步接入             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 7. 技术方案简述

### 7.1 技术栈

| 层 | 技术 | 理由 |
|---|---|---|
| 前端 | Vue 3 + TypeScript + Element Plus | 企业级后台的主流选择，生态成熟 |
| 后端 | Python + FastAPI | 异步原生、AI 生态友好、开发效率高 |
| 数据库 | PostgreSQL 14+ | JSONB 灵活存储 Agent 配置、RLS 多租户 |
| 缓存 | Redis 7 | 对话热缓存、限流、通知 Pub/Sub |
| 存储 | MinIO（S3 兼容） | Agent 图标、对话附件 |
| 部署 | Docker Compose + K8s（可选） | 降低部署门槛到一键启动 |

### 7.2 核心架构亮点

- **Agent 统一抽象模型**：`platform_config` + `capability` 两个 JSONB 字段，完整屏蔽 Dify/N8N/Coze 差异
- **插件化适配器**：`BaseAdapter` 抽象基类 + `AdapterRegistry` 注册表，新增平台只需 5 个方法
- **对话双写策略**：Redis 热缓存（最近 50 轮）+ PostgreSQL 冷归档，兼顾性能与持久化
- **多租户隔离**：共享数据库 + tenant_id 行级安全，标品默认方案零运维成本

> 详细技术设计参见 `01-系统架构总览.md` ~ `07-开发路线图.md`

## 8. 为什么是现在

### 8.1 市场时机

```
2024 ─── 2025 ─── 2026 ─── 2027 →

智能体平台爆发期            ← 我们现在在这里
  ├── Dify / N8N 快速成长
  ├── 企业大量部署
  └── 碎片化管理问题凸显 ──→ 统一门户需求爆发

预期 2027 年后，"企业智能体门户"将成为标配。
先发优势窗口期：6-12 个月。
```

### 8.2 团队能力匹配

- 熟悉 FastAPI + Vue 3 技术栈
- 有企业级平台开发经验
- 对 Dify/N8N/Coze 生态有深入理解
- 标品化思维：以产品而非项目的方式交付
