### 架构分层说明

| 层 | 职责 | 技术实现 |
|---|---|---|
| **客户端层** | 用户交互界面，支持 Web / H5 / 企微钉钉 / 开放 API | Vue 3 SPA + Axios + WebSocket |
| **接入层** | 统一入口、HTTPS 终结、限流、路由、WebSocket 代理 | Nginx / Kong / APISIX |
| **业务服务层** | 核心业务逻辑，按领域拆分为独立服务 | FastAPI 异步微服务 |
| **数据层** | 持久化存储、缓存、文件存储 | PostgreSQL + Redis + MinIO |
| **外部平台层** | 被适配的第三方 Agent 平台 | 适配器模式，插件化接入 |

## 3. 技术选型理由

### 3.1 前端：Vue 3 + TypeScript + Element Plus / Ant Design Vue

| 维度 | 选型理由 |
|---|---|
| **生态成熟度** | Vue 3 组合式 API + TypeScript 在企业级项目中被广泛验证 |
| **组件库** | Element Plus（侧重后台管理）和 Ant Design Vue（侧重门户体验）可按模块混用 |
| **状态管理** | Pinia（Vue 3 官方推荐，TypeScript 支持优秀） |
| **构建工具** | Vite（极速 HMR，生产 Rollup 打包） |
| **对标国内** | 国内企业技术栈主流为 Vue，招聘和社区支持充足 |

**不选 React 的理由**：目标用户群（企业 IT 管理员、业务用户）所在生态以 Vue 为主；Vue 的学习曲线对后续定制开发的客户团队更友好。

### 3.2 后端：Python + FastAPI

| 维度 | 选型理由 |
|---|---|
| **异步原生** | FastAPI 基于 Starlette + asyncio，天然支持高并发对话代理场景 |
| **自动文档** | OpenAPI (Swagger) 自动生成，降低前后端联调成本 |
| **类型安全** | Pydantic v2 提供请求/响应模型的强类型校验 |
| **AI/LLM 生态** | Python 是 AI 领域事实标准，后续可无缝集成 LLM SDK（LangChain、OpenAI 等） |
| **开发效率** | 语法简洁，依赖注入（Depends）机制清晰，适合快速迭代标品 |

**不选 Go/Java 的理由**：虽然性能更优，但本项目瓶颈在外部平台 API 调用（IO 密集），不在计算。Python 异步模型已满足需求，且 AI 集成成本更低。

### 3.3 数据库：PostgreSQL 14+ + Redis 7

| 组件 | 选型理由 |
|---|---|
| **PostgreSQL** | 成熟的关系型数据库，JSONB 支持灵活存储 Agent 配置；Row-Level Security 天然支持多租户隔离 |
| **Redis** | 高性能缓存，支持 Pub/Sub 用于实时通知，Stream 可用于轻量消息队列 |

### 3.4 部署：Docker Compose (开发) + K8s (生产可选)

| 阶段 | 方案 | 理由 |
|---|---|---|
| **开发/小规模部署** | Docker Compose 一键编排 | 5 个服务以内，Compose 足够；降低客户部署门槛 |
| **中大规模部署** | K8s Helm Chart | 弹性伸缩、滚动更新、多租户资源隔离 |

## 4. 核心设计原则

### 4.1 标品化优先 (Product-First)

- 所有功能设计面向"开箱即用"，提供合理的默认配置
- 可配置项必须有默认值，零配置可运行
- 提供品牌定制（Logo、主题色、企业名称）作为标品特性

### 4.2 多租户隔离 (Multi-Tenancy)

- **数据隔离**：PostgreSQL Row-Level Security + tenant_id 字段
- **配置隔离**：每个租户独立的平台连接、Agent 市场、权限策略
- **资源隔离**：Redis key 前缀按租户 namespace 隔离
- **租户模式**：支持"共享数据库 + 独立 Schema" 或"独立数据库"两种模式，标品默认前者

### 4.3 平台无关 (Platform-Agnostic)

- 统一 Agent 抽象模型，屏蔽 Dify/N8N/Coze 等平台差异
- 适配器模式实现插件化接入，新增平台不修改核心代码
- Agent 能力标准化：对话、工作流、知识库、工具调用统一描述

### 4.4 安全第一 (Security-First)

- JWT + RSA256 无状态认证，支持 Token 刷新与吊销
- RBAC（角色-权限）为核心，可扩展 ABAC（属性-权限）用于细粒度控制
- 所有外部平台 API Key 加密存储（AES-256-GCM + 租户级密钥）
- 审计日志全覆盖（谁、何时、做了什么、结果如何）

### 4.5 弹性与可观测 (Resilience & Observability)

- 服务间调用熔断、重试、超时（tenacity + httpx）
- 结构化日志（JSON 格式），对接 ELK/Loki
- Prometheus 指标暴露，Grafana 看板模板内置
- 健康检查端点（`/health`、`/ready`）支持 K8s 探针

### 4.6 渐进式复杂度 (Progressive Complexity)

- MVP 阶段功能最小化，快速验证核心价值
- 高级功能（推荐算法、BI 分析、SSO）在后续 Phase 按需扩展
- 架构预留扩展点（策略模式、事件总线），不提前实现

## 5. 关键非功能需求 (NFR)

| 类别 | 指标 | 目标值 |
|---|---|---|
| **性能** | API 响应时间 (P95) | < 200ms（读）/ < 500ms（写） |
| **性能** | 对话消息延迟 (首 Token) | < 2s（经门户转发） |
| **可用性** | 系统可用率 | 99.5%（单实例）/ 99.9%（K8s 集群） |
| **安全** | 认证方式 | JWT (RS256) + 可选 SSO (OIDC/SAML) |
| **安全** | 敏感数据存储 | AES-256-GCM 加密 |
| **容量** | 并发用户数 | 500（单实例）/ 5000+（K8s 水平扩展） |
| **容量** | 并发 Agent 对话 | 200（单实例） |
| **可观测** | 日志格式 | 结构化 JSON，含 trace_id |
| **可观测** | 指标暴露 | Prometheus `/metrics` 端点 |

## 6. 技术决策记录 (ADR)

### ADR-001：选择 FastAPI 作为后端框架

- **上下文**：需要异步 HTTP 框架，支持 WebSocket、自动 OpenAPI 文档生成
- **决策**：FastAPI over Django Ninja / Sanic / aiohttp
- **理由**：Pydantic 集成最成熟、社区活跃度最高、中间件生态丰富
- **影响**：放弃 Django ORM 生态，使用 SQLAlchemy 2.0 async

### ADR-002：采用共享数据库多租户模式（标品默认）

- **上下文**：标品面向中小企业，需降低运维复杂度
- **决策**：共享 DB + tenant_id 隔离，行级安全策略保障
- **理由**：运维成本低（一套 DB 实例），升级简单（一套 Schema 迁移）
- **影响**：需严格 review 所有查询带上 tenant_id 条件；大客户可选独立 DB 部署

### ADR-003：对话消息采用 Redis 热缓存 + PostgreSQL 冷归档

- **上下文**：对话消息读写频繁且需要低延迟，但不需永久热存储
- **决策**：最近 N 轮对话存 Redis（带 TTL），历史消息归档 PostgreSQL
- **理由**：Redis 提供微秒级读写，PostgreSQL 提供持久化和审计能力
- **影响**：需实现双写和回退读取逻辑；Redis 不可用时降级为纯 PostgreSQL

## 7. 架构演进预留

以下能力在当前版本不实现，但架构预留了扩展点：

| 能力 | 预留方式 | 预期引入 Phase |
|---|---|---|
| 向量检索 / RAG | PostgreSQL pgvector 扩展字段 + 适配器接口 | Phase 4 |
| 事件驱动架构 | Redis Stream / RabbitMQ 抽象接口（Common 层） | Phase 3+ |
| 多语言国际化 | Vue I18n + 后端响应 locale 参数 | Phase 2 |
| 使用分析与推荐 | 埋点事件表 + 离线分析任务 | Phase 4 |
| 企业 SSO (LDAP/SAML) | 认证中心策略接口 + 适配器 | Phase 4 |
